# Проверка сохранённых пар PKI

На Execution Node после завершения неудачного run:

```bash
sudo bash diagnose_pki_pairs.sh
```

Скрипт проверяет все пары `leaf.key`/`leaf.crt` под
`/var/lib/platform-installer/execution/pki`. Для другого корня PKI, одного проекта
или отдельного запроса передайте путь:

```bash
sudo bash diagnose_pki_pairs.sh /полный/путь/к/каталогу
```

Скрипт не изменяет файлы, не создаёт временных файлов и не подключается к сети.
Для `leaf.key`, `leaf.crt`, `request-fingerprint`, `keystore.p12`, `truststore.p12`
выводятся время изменения содержимого (`modified`), время изменения метаданных
(`changed`), размер, права и UID/GID владельца. Это не даты создания файлов.
Также выводятся SHA256 открытых ключей в формате SPKI DER и результат:

- `MATCH`: текущие ключ и сертификат соответствуют друг другу.
- `MISMATCH`: текущие открытые ключи различаются.
- `ERROR`: файл отсутствует, недоступен, является ссылкой или не разбирается.
  Это не доказательство несовпадения. Зашифрованный ключ без пустого пароля
  получает ERROR, интерактивного запроса пароля нет.

## Проверка keystore.p12

Если хранилище защищено непустым паролем, скрипт один раз запросит пароль через
терминал, со скрытым вводом. Используйте пароль PKCS12 из сеанса Installer.
Пароль применяется ко всем проверяемым хранилищам; если пароли различаются,
проверяйте каталоги запросов отдельно. Хранилище без пароля проверяется без ввода.
Для автоматизации есть `--password-stdin`: одна строка пароля читается до поиска
файлов. Пароль не передаётся через аргументы OpenSSL, окружение или файлы.
В отчёт не попадают ни пароль, ни закрытые ключи. При чтении PKCS12 закрытый
ключ проходит только по pipe непосредственно в OpenSSL для получения открытого
ключа; он не сохраняется и не выводится на терминал.

- `KEYSTORE_INTERNAL_MATCH`: ключ и конечный сертификат внутри PKCS12 совпадают.
- `KEYSTORE_KEY_MATCH`: ключ хранилища соответствует `leaf.key`.
- `KEYSTORE_CERT_MATCH`: сертификат хранилища идентичен `leaf.crt` (сравнивается
  весь сертификат DER, а не только его открытый ключ).
- `KEYSTORE_*MISMATCH`: соответствующие ключи или сертификаты различаются.
- `KEYSTORE_KEY_UNAVAILABLE` / `KEYSTORE_CERT_UNAVAILABLE`: исходный PEM
  не проверен; сравнение с ним невозможно, несовпадение не утверждается.
- `KEYSTORE_ERROR`: отсутствует файл, неверный пароль, повреждённый или
  неподдерживаемый PKCS12; это не доказательство несовпадения пары.

Проверка хранилища выполняется и после MISMATCH исходной пары. Это позволяет
увидеть, с каким из файлов согласовано хранилище. `truststore.p12` здесь получает
только метаданные: его содержимое и доверие CA эта диагностика не проверяет.

Сохранение безопасного отчёта:

```bash
sudo bash diagnose_pki_pairs.sh 2>&1 | tee pki-check.txt
```

Наличие `cmp` показано отдельно: диагностический скрипт работает без него,
но текущая проверка Installer в `pki_materialize/tasks/stores.yml` использует
эту команду и может сообщить о несовпадении при технической ошибке её запуска.
MATCH описывает файлы на момент проверки, а не их состояние во время сбоя.
Не запускайте диагностику одновременно с созданием/перевыпуском сертификатов.

Код выхода: 0 — все найденные пары совпадают; 1 — есть несовпадение или ошибка
пары или хранилища; 2 — ошибка запуска/поиска либо пары не найдены. Ошибка обхода каталогов
не выдаётся за полную успешную проверку. Содержимое stderr OpenSSL не выводится.
