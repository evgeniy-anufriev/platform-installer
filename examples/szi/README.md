# СЗИ — рабочий драфт пакетов

Это драфт для обсуждения, а не готовая установка. Исходные материалы обновлены
по `C:\Users\AnufrievEV\Codex\SZI_Update`: `manifests.7z`, `szi.7z`, четыре
архива образов и `dump.7z`. Ранее собранные файлы взяты с сервера 107.
Контейнеры не запускались, БД не восстанавливалась, Core не менялся.

Библиотека `szi` по-прежнему содержит пять обычных пакетов: `keycloak`,
`grant-access`, `grant-access-front`, `grant-access-audit`, `nginx`. Nginx
принадлежит СЗИ. Обновлены теги образов, переменные окружения, порты,
команды/entrypoint и монтирования по активным строкам новых манифестов.
Для этой единственной в проекте библиотеки СЗИ `applicationId` равен имени
пакета (`keycloak`, `nginx` и т. д.). Общее поле библиотеки
`instance_id_strategy: application-name` задаёт это для Core; остальные
библиотеки сохраняют прежние ID вида `<application-name>-<library-id>`.
Совпадение ID приложений между библиотеками должно блокировать план.
Четыре предоставленных архива образов соответствуют тегам первых четырёх
приложений; архива нового образа `nginx-docker-szi:794a4663` в папке нет.
Теги внутри всех четырёх архивов сверены с манифестами; из метаданных образов
также проверены штатные entrypoint/Cmd. Образы не импортировались в Docker и
не публиковались в runtime bundle.

В архиве `szi.7z` для темы Keycloak находятся только
`default_base/account/account.ftl` и пустой `applications.ftl`. Они наложены
на ранее собранный полный архив `themes.tar.gz`; остальные 1394 файла
сохранены. Новый архив содержит 1396 файлов, занимает 15 387 926 байт.
Архив тем и JAR-плагины Keycloak исключены из Git через `.gitignore`;
локальные файлы сохранены. Их необходимо предоставить отдельно перед
проверкой полного пакета: без них ссылки в `application.yml` не разрешатся.
Наличие пустого `applications.ftl` сохранено как в источнике; до запуска надо
подтвердить, что это намеренное удаление содержимого. Новый XML кеша и весь
набор JAR заменили прежние: в частности, добавился DMZ provision plugin,
убран прежний Kerberos plugin. Остальные файлы темы происходят от прежнего
Keycloak 24: совместимость с образом 26.4 не доказана. В активном манифесте
`KC_CACHE_STACK=jdbc-ping`, а предоставленный `cache-ispn.xml` задаёт стек
`tcp-ping`; без отсутствующей команды запуска агента нельзя определить,
какая настройка реально используется.

В Compose-шаблонах `environment` выводится из пакета defaults. Переменные
сверены с новыми активными манифестами. Для `grant-access` адреса Keycloak
и nginx выводятся из endpoint-групп соответствующих экземпляров СЗИ. Realm
(`SZI_REALM`, по умолчанию `master`) и имя кластера Hazelcast
(`HZ_CLUSTERNAME`, по умолчанию `<library_instance_id>`) задаются в
defaults библиотеки и могут переопределяться установкой. Адрес текущего узла
и список членов Hazelcast выводятся из размещений `grant-access`, адресов
серверов и эффективного опубликованного порта. В endpoint-настройках Keycloak
и nginx должны быть указаны опубликованные HTTPS-адреса; IP сервера 107 в
defaults не копируются.
Однако исходные `config.json`, `data.env`, `scada-lawellet.conf` и `script.lua`
пока содержат ручные адреса и маршруты. Их нужно превратить в шаблоны и
материализовать из того же набора параметров; текущие файлы — только
источники для такой работы.

Новые Keycloak, grant-access и grant-access-audit запускаются через Vault
Agent. В `manifests.7z` есть агентские файлы grant-access и audit, но нет
монтируемого каталога `keycloak/vault` и нет его `agent.hcl`. Агентские
конфиги, `role_id`, секреты и пароли в пакет не копировались. В defaults
объявлен стандартный режим `provisioner: vault-agent/process-supervisor`, но
`secret_bindings` и точные команды запуска агента ещё надо связать с
runtime-секретами; одно указание Vault entrypoint в Compose не создаёт
работающий агент. До этого пакеты не готовы к Apply. Исходные агентские HCL
также содержат `tls_skip_verify=true`, переносить их как готовую конфигурацию
нельзя. Исходный Keycloak задаёт `-Xmx8g` при лимите контейнера `6G`; это
противоречие требует решения перед запуском.

Исходный `nginx/default.conf` по-прежнему содержит демонстрационный OIDC
сервер с встроенным секретом и небезопасными параметрами. Файл исключён из
пакета и не монтируется; нужен отдельный проверенный конфиг образа.
`script.lua` перенесён как исходный код маршрутизации, но текущая проверка
содержимого конфигурации ошибочно отвергает его по словам `token`/`password`.
Реальные секреты из этого исключения не следуют и в пакет не разрешаются.

Оба файла `dump/keycloak_13-10-2026` и `dump/keycloak_14-10-2026` —
PostgreSQL custom-format (`PGDMP`) снимки БД. Они не входят в пакет
приложения: восстановление базы — отдельное изменение состояния PostgreSQL,
а не монтируемая конфигурация Keycloak. Другие дампы в архиве также не
относятся к декларации пакетов СЗИ.

Для полной темы обсуждается общее поле пакета:

```yaml
config_archives:
  - source: assets/themes.tar.gz
    format: tar.gz
    destination: themes
```

Core должен проверять архив и digest на Execution Node, передавать его на
выбранные target, безопасно распаковывать во временном каталоге экземпляра и
заменять `config/themes` только после успешной проверки. Нужны запрет выхода
за каталог, ссылок и специальных файлов, проверка дубликатов, владелец и
удаление устаревших файлов при повторном Apply. В драфте также предлагается
снять фиксированный предел 8 МиБ для объявленных конфигурационных файлов и
архивов и слепой фильтр содержимого по словам. Реальные секреты остаются
runtime-only; общие ресурсные пределы распаковки ещё предстоит определить.
Контракт пока не реализован, поэтому `package_inputs` остановится на архиве.

Интеграционные задачи для других библиотек пока не добавлены. Для них
единственным ключом экземпляра остаётся `applicationId`: client ID Keycloak,
subpath nginx, HAProxy endpoint, description и запись аварийного режима
выводятся из него и endpoint. Принятый URL клиента:
`https://nginx…/<clientId>/*`. Дамп и ручные записи из источника не становятся
источником идентичностей новых экземпляров.
