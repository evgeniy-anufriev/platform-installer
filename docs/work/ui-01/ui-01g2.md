# UI-01G2 — Certificates page and shared draft evidence

Document scope: the original milestone contract/design. Historical status, review
and QA checkpoints are collected separately; current status and authorization
are recorded only in [CURRENT_STATE](../../../CURRENT_STATE.md).

Recorded status and review scope: [historical checkpoint](evidence/documentation-checkpoints-20261012.md#ui-01g2-checkpoint-001).

The global **Certificates** navigation page is available for an open
Installer-managed project without a READY Execution Node. It follows the
accepted mockup order between Topology and Services and contains four compact
sections: Managed CA, Certificate profiles, TLS profiles and Certificate
scopes.

## Behaviour

- Create/update/delete produces only the v1alpha7 PKI typed intents added by
  UI-01G1 and uses the existing shared EditSession, Review, Save and Discard
  flow. It creates no second save lifecycle.
- Profile optional values stay omitted/inherited until deliberately selected.
  SAN policy controls distinguish **Inherited**, **Enabled** and **Disabled**;
  an explicit `false` is not confused with omission. Explicit empty `usages`
  survives complete update.
- Scope hosts, deployments and deployment-scoped members are selectable from
  the final shared draft state, including same-session topology edits. DNS and
  IP lists are direct desired inputs only; the UI computes no identity, SAN,
  provider VIP effect or PKI finding.
- TLS displays a masked runtime SecretRef label. It neither accepts nor shows
  a password, private key or secret content.
- The page has no Materialize, Reissue, service TLS assignment, Core call,
  Execution Node action or target contact. Those remain later milestones.
