# UI-01G1 — PKI contract and managed reopen evidence

Status: **DONE** (2026-09-17).

UI-01G1 introduces additive `project-edit/v1alpha7` for new Installer edit
sessions. It retains the v1alpha6 operation set, adds the four PKI entity
operation families, and normalizes them through the existing `EditCommand`,
structural Review, guarded local Save and direct managed-project reopen path.
It does not start UI-01G2, add a Certificates page, contact an Execution Node,
call Core, materialize PKI, or execute a target.

## Contract and safety evidence

- v1alpha7 accepts inherited provider reconcile/clear operations alongside
  PKI operations; older published versions remain compatibility inputs.
- PKI desired-state roots are read directly and boundedly from the owned
  managed document. Save materializes only the modified PKI family.
- Final-state references fail closed even if a referenced PKI root is absent.
  The graph covers CA/profile/TLS/scope relations, scope sources and the
  generic deployment `tlsProfile` reference.
- Internal PKI desired-state references use the exact published desired-state
  identifier grammar (1–128 characters, leading lowercase letter, and the
  permitted `.`, `_`, `-` separators). This does not broaden Installer command
  IDs.
- PKI integer fields accept native YAML integers and JSON-decoded `float64`
  only when finite, integral and safely representable. Fractional, non-finite
  and overflow values are rejected without rounding.
- Optional `usages` may be absent; when present it must be an array. `null`,
  scalar and object values are rejected.
