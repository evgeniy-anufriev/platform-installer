# UI-01H1 — safe service-configuration foundation

Document scope: the original milestone contract/design. Historical status, review
and QA checkpoints are collected separately; current status and authorization
are recorded only in [CURRENT_STATE](../../../CURRENT_STATE.md).

Recorded status and review scope: [historical checkpoint](evidence/documentation-checkpoints-20261012.md#ui-01h1-checkpoint-002).

UI-01H1 adds additive immutable `project-edit/v1alpha8`. New sessions emit
v1alpha8; v1alpha1 through v1alpha7 remain compatibility inputs. The one
existing `EditCommand`, shared EditSession and guarded local structural Save
are reused for deployment- and member-scoped `SetServiceConfigurationValue`
and `RemoveServiceConfigurationOverride` operations.

Only a closed catalog descriptor vocabulary is projected to the Installer:
`BOOLEAN`, bounded `INTEGER`/`NUMBER`, closed `ENUM`, bounded safe `STRING`,
and a trusted `ui.x-referenceKind: TLS_PROFILE` selector. Unknown strings,
objects, maps, secrets/credentials and unapproved reference semantics remain
read-only and writer-preserved; their raw values do not reach React.

TLS profile references are derived exclusively from the exact
project-lock-bound READY catalog descriptor, for both deployment and member
configuration. `DeleteTLSProfile` requires that exact catalog and fails closed
when it is unavailable or incompatible. No setting name is special: an
unannotated string named `tlsProfile` is not a TLS reference.
