# UI-01G3 — Verified Core PKI evidence

Document scope: the original milestone contract/design. Historical status, review
and QA checkpoints are collected separately; current status and authorization
are recorded only in [CURRENT_STATE](../../../CURRENT_STATE.md).

Recorded status and review scope: [historical checkpoint](evidence/documentation-checkpoints-20261012.md#ui-01g3-checkpoint-001).

UI-01G3 adds a narrow, read-only `VerifiedPKIView` at the Go-to-Wails
boundary. It consumes the existing target-free Project Verify result; it does
not add a Core protocol operation, desired-state store or PKI lifecycle.

## Behaviour

- The view is `CURRENT` only when the saved revision, selected explicit
  Execution Node and immutable runtime evidence exactly match the verified
  Core snapshot.
- It copies only bounded typed certificate identity fields: derived identity
  ID/scope, TLS profile ID, DNS/IP SAN values and consumer placement identity.
  It rejects malformed or oversized PKI data as `UNAVAILABLE`, with no partial
  identity/SAN rows.
- `INVALID` passes through safe Core findings only; `STALE`, `NOT_VERIFIED`
  and `UNAVAILABLE` never show identity/SAN data. A structural draft, Save or
  Execution Node switch clears prior preview state.
- Certificates now shows the existing Project Verify action and an evidence
  area. `CERTIFICATE_REISSUE_REQUIRED` remains visible as a Core finding and
  is never bypassed or downgraded.
- The existing managed TLS-profile ID collection is the selector seam for
  UI-01H. No Services editor, TLS assignment, materialization, reissue,
  playbook dispatch or target contact is added.
