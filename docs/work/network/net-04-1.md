# NET-04.1: Keepalived HAProxy health tracking

Document scope: the original milestone contract/design. Historical status, review
and QA checkpoints are collected separately; current status and authorization
are recorded only in [CURRENT_STATE](../../../CURRENT_STATE.md).

NET-04.1 activates opt-in HAProxy readiness tracking for a Keepalived VRRP
deployment. It does not change DNS, HAProxy routing, endpoint resolution,
VRIDs, priorities or `nopreempt` semantics.

## Contract

A Keepalived deployment opts in explicitly:

```yaml
configuration:
  haproxyHealthTracking:
    serviceDeploymentRef: haproxy
```

Core validates the referenced deployment exists, is HAProxy, uses the same
endpoint group, and is placed on every participating Keepalived host. Without
this setting, rendered configuration contains neither `vrrp_script` nor
`track_script`.

When enabled, Keepalived owns one root-owned `0750` helper. The helper requires
both an active local HAProxy unit and a bounded, read-only response from its
admin socket. The rendered script and `track_script` deliberately have no
weight: a failed helper makes the local VRRP instance ineligible rather than
merely reducing its priority.

## Cluster activation barrier

The package playbook is a three-phase lifecycle:

1. Every participant renders and natively validates its candidate.
2. Barrier A permits installation only when every candidate passed.
3. Every participant installs the exact candidate, proves candidate and active
   SHA-256 equality, and natively validates the active file.
4. Barrier B permits service reconcile only when every active validation passed.

No single-host role `apply` phase exists. The standard playbook supplies the
explicit phases, so no role invocation can bypass the cluster barriers.

Candidate checksums are execution evidence only and are never persisted in
`platform_generated_state`.

## Verification and acceptance

Read-only verification checks Keepalived and HAProxy service state, helper
owner/mode/content and result, active `vrrp_script`/`track_script`, absence of
`weight`, `BACKUP`/`nopreempt`, and all-or-none configured VIP ownership.
