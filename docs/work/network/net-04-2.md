# NET-04.2 — service-driven provider reconciliation

Document scope: the original milestone contract/design. Historical status, review
and QA checkpoints are collected separately; current status and authorization
are recorded only in [CURRENT_STATE](../../../CURRENT_STATE.md).

## Purpose

После успешного lifecycle сервиса общий integration stage заново строит полную
модель BIND и HAProxy из canonical Ansible desired state. Нового DTO,
хранилища desired state или imperative API не создаётся.

## Contract and lifecycle

`serviceDeployment.endpointGroup` выбирает DNS и определяет HAProxy через
Keepalived с таким `endpointGroupRef`: Core пересекает заданные серверы
Keepalived с размещениями HAProxy той же группы. Выбираются все подходящие
provider/host пары; полного покрытия VIP не требуется. Legacy
`haproxy.deploymentRef` принимается, но не влияет на выбор. Настройки
`haproxy.backend` сохраняются и переопределяют package-owned
`x-haproxyBackendDefaults`. Для ClickHouse, Vault, Redis и PostgreSQL владелец
согласовал roundrobin, check=true, fall=3, rise=2, ssl=true, sslVerify=required.
Отсутствие HAProxy даёт `HAPROXY_ENDPOINT_PROVIDER_NOT_FOUND` в Core журнале
и отдельный SKIPPED, не прекращая установку. Недоступный выбранный provider
сохраняет существующее fail-stop поведение.

Частичная настройка выполняется только на выбранных серверах; полный reconcile
фильтрует backend и managed inventory по тем же серверам. При переносе
source частичный hook не обнаруживает прежние исключённые серверы. Удаление
оставшихся там fragments требует существующего полного reconcile на прежних
HAProxy, пока они остаются в inventory. Удалённый из inventory сервер этим
путём не обслуживается. Новое хранилище прежних целей не вводилось.

`source changed=0` не отменяет provider reconciliation. Resolver read-only,
детерминированно deduplicates provider IDs и предотвращает provider recursion.

## Full-model providers

Providers не получают imperative add/delete API. Они строят полный DNS
zone/backend graph из canonical state, валидируют candidate и активируют exact
validated graph. BIND сохраняет native secondary transfer; HAProxy создаёт
один `30-backend-<deployment>-<group>.cfg` на backend, удаляет только stale
Platform-managed fragments и сохраняет third-party `conf.d` files.

EndpointGroup provider выбирается по ID, а не domain: same-domain exact groups
поддерживаются; DNS wildcard ownership валидируется отдельно от PKI wildcard.

## PKI and PostgreSQL

Один project-wide PKI context использует CertificateIdentity:
`tlsProfileRef + scope + resolved scope identity`. Legitimate consumers делят
leaf/private key, а SAN — детерминированный union. Endpoint сам по себе не
создаёт PKI consumer.

PostgreSQL проверяет serving/materialized TLS leaf, делает `pg_ctl reload`
только при mismatch и блокирует credential DDL при TLS verify failure.
Replication credential reconcile выполняется только при failed auth probe.
