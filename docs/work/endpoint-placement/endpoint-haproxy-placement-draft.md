## Цель

Убрать отдельный выбор HAProxy у сервиса. Привязка сервиса к endpoint group
определяет DNS и поиск размещений HAProxy через связанный Keepalived.
В текущем `full-services` ClickHouse и Vault имеют `qa-shared-endpoint`,
но отсутствие явного `haproxy.deploymentRef` не позволяет существующему
Core создать их backend. Новая схема устраняет эту дополнительную привязку.

## Согласованный выбор размещений

1. Получить `endpointGroup` сервиса из канонического проекта.
2. Найти связанный Keepalived по `endpointGroupRef`.
3. Получить серверы заданного размещения Keepalived.
4. Найти заданные размещения HAProxy той же endpoint group на этих серверах.
5. На всех найденных серверах создать или обновить backend данного сервиса.

Поиск выполняет Core по desired state и inventory. Он не использует
обнаруженные процессы как источник отношений и не устанавливает HAProxy
автоматически. Проверка фактического состояния выполняется при apply/verify.

Владелец явно исключил следующие блокировки:

- отсутствие HAProxy на части потенциальных владельцев VIP;
- неоднозначность из-за нескольких подходящих HAProxy;
- дополнительную проверку количества HAProxy на одном сервере.

Применять ко всем подходящим размещениям. Риски выбранного размещения
принимает пользователь; эта схема не вводит обязательное полное покрытие VIP.
Существующие проверки вне перечисленных ограничений не отменены автоматически.

## Отсутствующий HAProxy

Если подходящих размещений нет, записать **ошибку**
«HAProxy для endpoint не найден» в общий журнал Core и отметить соответствующее
действие интеграции как пропущенное. Продолжить установку; этот случай
не отменяет установку сервиса и не останавливает последующие действия.

Не подменять ошибку информационным сообщением или успешным выполнением
backend-интеграции. В реализации определить структурированное представление
ошибки и пропуска в существующих Finding/Event/Result контрактах, включая
агрегированный terminal результат; новый параллельный формат логов не вводить.

## Настройки backend и совместимость

Убрать влияние `haproxy.deploymentRef` на выбор провайдера. Параметры
`haproxy.backend` сохранить: они продолжают задавать разрешённые настройки
балансировки, проверок и соединения с backend.

Порты участников, протокол и TLS брать из существующих package metadata и
разрешённой конфигурации Core. Не вычислять их в Go/React и не считать
одинаковыми для всех участников. Дополнительного ручного выбора провайдера
для этого не требуется.

В плане реализации описать совместимость старых проектов, проверки схемы
и управляемую миграцию. Не переписывать старый desired state молча при чтении.

## Обновление, перенос и удаление

Операция затрагивает только backend конкретного сервиса. Остальные backend
и чужие конфигурационные файлы сохранить.

На каждом сервере: подготовить изменение, проверить результирующую
конфигурацию HAProxy и атомарно активировать её. Не обещать распределённую
атомарность между серверами; частичное применение отражать в результате.

При удалении связи или переносе учитывать прежние узлы. В плане операции
должны быть доступны прежние и новые цели, чтобы удалить старый backend
и создать новый даже после изменения endpoint group или размещения провайдера.
Недоступные прежние узлы остаются незавершёнными действиями для повтора.

Источник прежних целей и механизм восстановления необходимо определить
в плане реализации через существующие derived/runtime evidence. Не вводить
второе хранилище desired state или UI-owned историю инфраструктурных отношений.

## Границы изменений

Изменение касается Core-разрешения отношений, зависимостей плана,
host-scoped backend-интеграции, apply/verify, событий и восстановления.
Существующее согласование полной модели HAProxy нельзя автоматически
использовать для удаления посторонних backend в операции одного сервиса.
Нужно согласовать новые операции с полным apply HAProxy, чтобы последующий
запуск провайдера не отменял созданные backend.

Go остаётся оркестратором; React отображает отношения и результаты Core.
Standalone Ansible-путь должен работать без Go/UI.

## Предварительные проверки

- ClickHouse и Vault: DNS, HTTPS через VIP, backend на найденных узлах.
- Неполное пересечение Keepalived/HAProxy: установка разрешена, применено
  только на найденных узлах.
- Несколько подходящих размещений: применено ко всем без выбора первого.
- Нет HAProxy: ошибка в журнале, интеграция пропущена, установка продолжается.
- Параметры backend и разные порты участников сохранены.
- Удаление/перенос: прежние фрагменты удалены, новые созданы; другие сервисы
  и чужие файлы не изменены.
- Ошибка проверки candidate, недоступный узел, отмена и повтор:
  активная конфигурация защищена, незавершённые действия доступны для повтора.
- Повтор неизменённого запуска: `changed=0` без лишнего reload.
- Старый проект с `deploymentRef`: согласованная совместимость/миграция.
