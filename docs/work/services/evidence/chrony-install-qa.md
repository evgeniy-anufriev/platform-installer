# Chrony через Installer на RED OS 8.0.3

4 ноября 2026 года. Код сервиса `6cca5c34`, ветка `codex/chrony`.

- Wails dev bridge на loopback подтвердил вызовы реальных методов Go. Старый preflight считал ответ `PROJECT_NOT_OPEN` ошибкой моста. Исправленный preflight подтверждает вызов `GetApplicationConfig` и отдельно сообщает, что проект ещё не открыт. Сообщения Wails dev `runtime:ready` и ошибка `nodes` в `/wails/ipc.js` наблюдались, приёмку не прервали.
- Набор собран на RED OS node2 с платформой `redos:8.0.3:x86_64` и опубликован штатным publisher в cache отдельного worktree. Digest `sha256:34974fd1dcce97a0a8a2bdeb90ee720fac1818e3d88be2f35443eb52998161a2` совпал с lock проекта и runtime плана. Узел выполнения node1 подготовлен через UI до READY.
- В проекте **Chrony QA 803** через React/Wails сохранён один экземпляр `qa-chrony` с сервером node1 (`192.168.56.101`) и клиентом node3 (`192.168.56.103`). Проверены и подтверждены SSH-отпечатки обоих хостов по доверенному known_hosts. На сервере разрешена сеть `192.168.56.103/32`, клиенту задан источник `192.168.56.101`.
- Project Verify вернул VERIFIED для ревизии `sha256:ae110ea4ba584573a18c235704f965c88160a150291bdc0db2a84c8bae993705`. План `plan-0e256963359e3df1f937ece5` содержал только Apply и Verify этого экземпляра на обоих хостах. Запуск выполнен кнопкой «Одобрить и начать установку». Run `installer-eeb1ef3586e833cc0368139b934535f0` завершился SUCCEEDED, sequence 157.
- Журнал выполнения подтвердил порядок. Запись конфигурации и перезапуск сервера завершились на sequence 107/110, клиента на 120/123. Verify клиента подтвердил синхронизацию на sequence 155. На сервере проверка синхронизации была пропущена по роли.
- После завершения оба `chronyd` были active. Сервер слушал UDP/123. На клиенте `chronyc -N -c sources` показал выбранный источник `^,*,192.168.56.101` со stratum 10, а `chronyc tracking` показал stratum клиента 11 и `Leap status: Normal`.

На обоих хостах уже стоял штатный RPM `chrony-4.4-2.red80.x86_64`. Apply применил конфигурацию и перезапустил службу. Установка RPM на чистом хосте, офлайн-доставка RPM и повторный Apply в этот прогон не входили. Конфигурация Chrony оставлена на тестовых хостах. Исходные файлы сохранены в локальных резервных копиях на каждом хосте.
