## Повторный прогон после восстановления стенда

- На RED OS 101 в журнале старта HAProxy и Keepalived зафиксированы тайм-ауты systemd. `haproxy -c` и `keepalived --config-test` вернули 0. После штатного запуска оба unit стали `active`. На 102 оба сервиса уже работали, VIP `192.168.56.111` оставался на 102. Проверен работающий rootless Docker на 101 под `platform-automation` через локальный сокет и TCP 2376. Системный Docker unit остался неактивен.
- Настроена каноническая ссылка на Docker-пароль в изолированном проекте. Соответствие существующего QA-пароля действующей учётной записи проверено без изменения учётной записи. Docker и PKCS#12 значения приняты в сессию Installer через штатные Go bindings. В проекте хранятся ссылки. Для 101 и 102 сверены SSH-отпечатки перед запуском через UI.
- Повторный BuildDeploymentPlan вернул `EXECUTABLE` для полной и прикладной областей. Для исполнения выбрана прикладная область с единственным изменяющим действием `APPLICATION_LIBRARIES_APPLY` на 101 и 102. Запуск `installer-244122e03eedcb92a4e6c3b0ea54ec5a` завершился `FAILED` на подготовке образа с `APPLICATION_IMAGE_NOT_LOCKED`. В авторскую фикстуру добавлен разрешённый внутренний QA-registry только для узла 101. Тестовый манифест доступен по HTTPS.
- Запуск `installer-13367a21844b5b782e6e033aa472bbe9` прошёл проверку метаданных образа и завершился `FAILED` с `APPLICATION_RENDER_REQUIRED`. Добавлен недостающий базовый Compose-шаблон в тестовую библиотеку. Исходники роли HAProxy и DNS не менялись.
- Запуск `installer-5062a8956cafc4af42e072747722d76d` остановился на сверке Compose с проекцией Core. В шаблоне фикстуры добавлены команда, метки владельца и полный список портов из проекции. Следующий запуск `installer-16fbd04457ca2a0c5d1e887492a54357` прошёл сверку, но Compose не смог создать экземпляр. Проверка rootless Docker показала, что подсети из стандартного пула были заняты либо пересекались с сетью стенда. В Compose тестовой библиотеки задана отдельная свободная подсеть. Существующие сети и настройки Docker сохранены.
- Реальный React/Wails: Verify `VERIFIED`, план `plan-e4e124abc4486cdb3e431d79` с состоянием `EXECUTABLE`, ревизия `sha256:f64472c7a07226f0985c8849eea153f26ea3b78fd4e6b7b535e16d56f5ee2cc3`.
