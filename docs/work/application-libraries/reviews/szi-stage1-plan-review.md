## SZI-P01 — порядок библиотек (BLOCKING, OPEN)

План требует полностью завершить СЗИ до зависимых библиотек, но не задаёт контракт зависимости и порядок всех стадий. Сейчас Core обходит библиотеки по отсортированному ID (`application_libraries.py`), а общий `application-libraries-provider-stage.yml` создаёт ресурсы всех библиотек до запуска любого приложения. При выборе `sdku` и `szi` порядок ID обратный; ресурсы СДКУ могут измениться до работоспособности СЗИ.

Минимальная коррекция: явная зависимость в существующем библиотечном контракте, проверка циклов и последовательное выполнение provider/application стадий по библиотекам. Проверить совместный Apply и отказ на каждом этапе СЗИ: до завершения СЗИ мутаций СДКУ нет.

## SZI-P02 — endpoint до публикации (BLOCKING, OPEN)

`create-admin` использует endpoint Keycloak, но `after_ready` запланирован до общего endpoint stage. Первый bootstrap зависит от маршрута, который ещё не создан.

Минимальная коррекция: передать доступный до публикации HTTPS-адрес из resolved placement, определить TLS identity и сетевой путь от выбранного target. Публичный endpoint проверять после его штатной публикации. Проверить первый Apply без ранее существовавшего nginx/HAProxy маршрута.

## SZI-P03 — исполнимый bootstrap CLI (BLOCKING, OPEN)

План вызывает `bootstrap-admin service` до Compose startup через общий host script runner, но не определяет источник Keycloak CLI, доступ к PostgreSQL, монтирования и runtime secret. В текущем `activate_instance.yml` доставка образа находится после предлагаемой фазы `before_start`.

Минимальная коррекция: описать CLI-запуск из того же проверенного образа с нужной runtime projection, изоляцией и очисткой; доставку образа перенести до `before_start` без SZI-специфичной ветки в Core. Проверить холодный старт, повтор и обрыв CLI.
